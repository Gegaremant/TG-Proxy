  на живую, не выключая туннель.

# Release 1.2.6

## Linux: трей «не отзывается» (главный фикс)

* Разобрали на живом стенде (Debian 13 / X11): у бэкенда pystray `xorg`
  поддержка меню в принципе отсутствует — обработчик `_update_menu` — пустая
  заглушка («Menus are not supported on X»). Сборки без GTK/appindicator
  падают в этот бэкенд: иконка в трее есть, а клики молчат.
* Теперь при старте бэкенд распознаётся и логируется; на `xorg` приложение
  само открывает окно настроек (все действия доступны из него), а клик
  левой кнопкой по иконке выполняет действие по умолчанию — «Открыть в
  Telegram».
* Второй слой той же боли: побочный `tkinter.Tk` от раннего диалога
  (например, ошибка старта прокси) перехватывал роль
  `tkinter._default_root`, и все последующие окна настроек падали с
  «RuntimeError: main thread is not in main loop» — молча, только в лог.
  Теперь messagebox-окна и CTkToplevel явно живут в интерпретаторе
  скрытого CTk-корня — окна открываются как положено.
* Установочный скрипт переименован в `install_TG-Proxy.sh` (обновлены
  README, LINUX_INSTALL и сборочные workflow).

## Android

* «Автонастройка» больше не «подбирает и забывает»: после подбора SNI и
  CF-доменов прокси перезапускается автоматически, как это делает

# Release 1.2.4

## Windows/Linux/macOS: трей выдавал нерабочую ссылку (главный фикс)

* **Причина «не подключается вообще» на Windows**: кнопки «Открыть в
  Telegram»/«Копировать» в трее всегда выдавали dd-ссылку (`dd<secret>`),
  даже когда прокси работает в EE-режиме с Fake TLS. Клиент, добавленный
  по dd-ссылке, получает от прокси HTTP-редирект вместо подтверждения —
  ни одно подключение не завершалось (в логе: тысячи попыток, `pool=n/a`,
  `masked=1`).
* Теперь `tg_proxy_url` учитывает `fake_tls_domain` и выдаёт EE-ссылку
  вида `ee<secret><hex-домен>` — как печатается в логе при старте.
  Исправление действует для всех трёх ОС (общий код трея).
* После обновления нужно **заново добавить прокси в Telegram** по ссылке
  из нового трея (старую dd-запись удалить).
* Фоновая диагностика: при невозможности поднять WS-пул причина последнего
  отказа пишется в INFO-лог (раньше — только в DEBUG).
* Проверено на живом стенде в цензурированной сети: EE-клиент → CF-fallback
  → WS до Telegram поднимается за ~0.15 c.

## Android: экран готовности к запуску

* Когда прокси не запущен, на главном экране остаются только «Запустить»
  и чек-лист готовности (энергосбережение / сеть без ограничений /
  автозапуск / автоподключение / работа в фоне / уведомления) — у
  невыполненных пунктов кнопка «Включить», у выполненных галочка.
* Кнопки «Автонастройка», «Скопировать ссылку», «Открыть в приложении
  Telegram» показываются только пока есть соединение.
* При каждом запуске приложения проверяются все пункты готовности; если
  что-то не включено — предлагается включить (диалог со списком).
  Прежний диалог «включить автоподключение» заменён универсальным.
* Кнопка отключения энергосбережения стала частью чек-листа.

## Android: стабильность отключений

* **Keepalive-пинги вместо обрыва**: при таймауте чтения внутри кадра
  WebSocket (`RawWebSocket`) отправляется ping-кадр, а чтение возобновляется
  с сохранённого состояния кадра — соединение больше не рвётся из-за
  «тишины» в канале.
* **Перебор всех CF-доменов**: `WsPool.connectOne` перебирает каждый домен
  из списка, а не только первый; рефилл пула с экспоненциальным бэкоффом
  (1с → 60с) вместо спама переподключениями.
* **Health-трекинг доменов**: `CfDomains` отслеживает неудачи и успехи
  (strike → кулдаун 1–10 минут,healthy-домены в приоритете); ранние обрывы
  Cloudflare (<15с при >100 КБ) считаются неудачей, долгоживущие соединения
  (≥60с) — успехом.
* **Починка битого домена**: значение CF-домена схематически чистится от
  `proxy://` и прочих префиксов (`ProxyConfig.cfProxyDomain`).
* **Автопроверка подключения при старте**: новый переключатель в настройках
  (по умолчанию включён) — можно отключить проверку Telegram API при запуске.
* Кнопка «Автонастройка» перенесена на главный экран.
* **Исправлен краш при смене языка**: применение сохранённой локали через
  `attachBaseContext` + `recreate()` вместо хака с `CompositionLocalProvider`.

## Десктоп: восстановленные функции

* **Fake TLS домен** снова редактируется в настройках и теперь действительно
  применяется к конфигурации прокси (`fake_tls_domain` в `apply_proxy_config`).
* Восстановлены: кнопка **Auto Config** (автоподбор SNI-домена по пингу),
  кнопка **GitHub** в шапке, ссылка на документацию и проверка Telegram API
  при первом запуске.

## CI: стабильная подпись Android и починка Desktop Build

* **Android APK теперь обновляется поверх предыдущей установки**: каждый прогон
  GitHub Actions раньше генерировал новый debug-ключ, поэтому подпись менялась
  с каждой сборкой и обновление падало с `INSTALL_FAILED_UPDATE_INCOMPATIBLE`.
  В CI добавлен шаг восстановления стабильного debug-ключа из секрета
  `ANDROID_DEBUG_KEYSTORE` — подпись всех сборок теперь одинаковая.
  **Важно:** если на телефоне стоит версия, собранная до этого фикса,
  её подпись другая — один раз удалите старое приложение и установите новое;
  дальше обновления будут ставиться поверх.
* **Исправлен Desktop Build (Linux)**: после слияния с upstream
  `packaging/linux.spec` требует полный GI-бандл (GTK3, AppIndicator/Ayatana,
  typelib'ы DBus), а workflow ставил только `python3-dev`. Linux-сборка
  вынесена в отдельный job на `ubuntu-22.04` с системным Python,
  `venv --system-site-packages` и нужными apt-пакетами (как в апстриме).
  Windows/macOS собираются по-прежнему, падение одной ОС больше не отменяет
  остальные (`fail-fast: false`).

## Android: интерфейс и стабильность подключения

* **Кнопки на главном экране**: «Автонастройка», «Копировать» и
  «Открыть в приложении Telegram» теперь доступны **всегда** — и при
  запущенном, и при остановленном прокси. При запущенном прокси рядом с
  «Остановить» появилась кнопка «Переподключить» (раньше она была только
  в настройках).
* **«Open in Telegram» → «Открыть в приложении Telegram»**.
* **Автонастройка проверяет доступность API**: кроме замера SNI-доменов она
  теперь опрашивает CF-домены (`wss://kws{DC}.{domain}/apiws`) и оставляет в
  пуле только те, что реально отвечают. Половина публичных доменов мертва в
  любой момент, и мёртвый домен стоил полного таймаута подключения на
  каждом новом клиенте. При старте прокси та же проверка выполняется в фоне
  (если включена «Автопроверка»).
* **Закрепление рабочего домена за DC**: прокси больше не выбирает CF-домен
  случайно для каждого соединения — сначала пробуется тот, что уже
  сработал для этого DC.
* **Короткий таймаут подключения к CF-пулу** (5 с вместо 10) и явные
  сообщения в логе вместо молчаливых обрывов.
* **Диагностика в логах**: в лог пишется код закрытия WebSocket и код
  ошибки MTProto, который прислал Telegram DC (раньше было видно только
  «8 байт от сервера» без объяснения).
* **Ссылка на прокси использует реальный порт**: если настроенный порт
  занят и прокси занимает следующий, в ссылку теперь подставляется именно
  тот порт, на котором прокси слушает.
* **Автоподключение** (новое): по умолчанию выключено, на первом запуске
  приложение предлагает его включить; тумблеры «Автоподключение» и
  «Автозапуск при загрузке устройства» — в настройках.

# Release 1.0.5

## Исправление подключения (главное)

* **CF-домены снова работают.** Убран жёсткий подбор IP дата-центров: теперь в режиме Cloudflare прокси идёт в CF-проксированный домен напрямую (как в референсном Rust-прокси), а не на заблокированный `149.154.167.220`.
* Исправлен порядок fallback: `CF-домен пользователя → CF Worker → CF-пул → прямой WebSocket → закрытие с остыванием`.
* Прямой WebSocket теперь умеет повторять попытку соединения через доменное имя (резолвится через DNS), а не только по захардкоженному IP.

## Медиа-каналы

* **Исправлен media-фолбэк.** Для медиа-каналов (DC2 media, DC4 media) теперь используется хост `kws{dc}.{домен}` без суффикса `-1`, как в референсной реализации. Раньше медиа-каналы падали с `UnknownHostException`, потому что хоста `kws{dc}-1.{домен}` не существует.

## DNS-over-HTTPS

* Добавлен резервный резолвер **DoH (DNS over HTTPS)** на случай, когда системный DNS не может разрешить CF-домены.
* Используются публичные DoH-серверы: Cloudflare (`1.1.1.1`), Google DNS (`8.8.8.8`), Quad9 (`9.9.9.9`), AdGuard (`94.140.14.14`) и ваш провайдерский `xbox-dns.ru` (DoH).

## Upstream SOCKS5

* Добавлена поддержка **upstream SOCKS5** (например, Hiddify `127.0.0.1:2334`) — весь исходящий трафик прокси можно пускать через сторонний SOCKS5-прокси.
